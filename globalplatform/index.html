Architecture

Keep transport, registry and policy distinct.

The kernel owns APDU transport, registry mutation, object ancestry and lifecycle checks. A selected Security Domain supplies administrative policy, discovery data, Secure Channel establishment and protected-APDU transforms. Hardware interfaces remain part of the kernel port.

Not a drop-in RTOS library.oXiDe SE is a Secure Element OS research platform. Integrating it with a main operating system requires board and interface work. TrustZone integration remains a direction, not a completed capability.

Practical path

Move from a neutral SD to delegated SCP.

  1. Read the guided example.Start with the versioned Security Domain tutorial and its role model.
  2. Choose the right reference.simple_security_domain is a neutral starting point. Its empty trait implementation advertises no SCP and rejects establishment commands. complete_security_domain contains the fuller administrative implementation.
  3. Declare the SD.Copy a validated manifest, point it at your Rustlet-backed Security Domain and preserve the explicit protocol and key configuration.
  4. Build native ELF.Produce target/kernel/firmware/kernel.elf, then run the documented APDU exchanges and test scenario.
  5. Study the authority model.Continue into the developer and kernel architecture guides for registry ownership, SCP03/SCP11 and persistence.
Declaration alone does not add a protocol.A Rustlet that merely implements the Security Domain trait does not inherit SCP from the kernel. Support must be implemented and advertised explicitly.

Research boundaries

Evaluate with the open work in view.

  • Functional random-number tests do not establish an entropy bound; source qualification remains open.
  • Normal Security Domain hook rejection still has an incomplete live-state rollback path.
  • Rustlet-backed Security Domain execution is covered, but dynamic loading of every new Security Domain deployment path is not exhaustively qualified.
  • Pico 2 is validated on hardware through OpenOCD; Pico 2 QEMU support is not claimed.

Use the versioned TODO as the current source for these limits instead of treating this summary as a conformance or certification claim.
