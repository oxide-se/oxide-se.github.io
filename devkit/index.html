Run your first Rustlet.

A short physical-board path from a ready-built Pico image to your first CA FE response.

First outcome

A running devkit image, one dynamically loaded Rustlet and a successful APDU exchange.

Before you begin

This is the quick start.

Looking for the complete walkthrough?The versioned Getting Started covers prerequisites, local firmware builds, OpenOCD, troubleshooting and the other supported targets. The shorter path below uses a ready-built UF2 on a physical Pico 1 or Pico 2.

You need a development Pico, a USB data cable and a 3.3 V UART bridge connected to GPIO0 (Pico TX), GPIO1 (Pico RX) and ground. The UART runs at 115200 baud, 8N1, without flow control.

Download and prepare

Get the image and the tools.

  1. Download the UF2 for your board.Use the Pico 1 image or the Pico 2 image. Checksums and ELF variants are available on the Downloads page.
  2. Clone the matching release.The source, Rustlet ABI and ready-built images are all pinned to v1.0.0-beta.1.
  3. Build the host client.Initialize the FAE build helper, then compile apdu_tool.
git clone --branch v1.0.0-beta.1 \
  https://github.com/oxide-se/oxide-se.git
cd oxide-se
git submodule update --init tooling/build-fae
cargo build -p apdu_tool

If a required host tool is missing, stop here and follow the versioned setup instructions.

Install and boot

Start the devkit and read its ATR.

  1. Install the image.Hold BOOTSEL while connecting the Pico over USB, release it, then copy the matching UF2 to the mounted drive. It is named RPI-RP2 on Pico 1 and RP2350 on Pico 2.
  2. Wait for the ATR.With the UART bridge connected, start the command below from the repository root. Replace the serial device with yours.
  3. Reset the Pico.Press Reset after apdu_tool is waiting. The ATR is emitted only once at boot.
target/debug/apdu_tool -v \
  --serial /dev/ttyACM0:115200 \
  --connect-timeout 120s \
  --atr-timeout infinite atr

On macOS, use the matching /dev/cu.usbmodem... device. On Windows, use a value such as COM3:115200. The expected ATR is:

3B 1C 11 80 56 09 C1 DE 5E 10 00 73 80 00 00

The successful command creates session.json. Keep running the following commands from the repository root so they reuse that connection.

The UF2 erases the complete flash.It removes previously installed Rustlets and persistent data. Use a development board whose contents may be replaced.

Build and load

Make the template answer CA FE.

In rustlets/rustlet_template/src/main.rs, replace the existing match apdu.ins() expression with:

match apdu.ins() {
    0x04 => apdu.as_sending().send(&[0xCA, 0xFE]),
    _ => apdu.reject(ApduStatus::instruction_not_supported()),
}

Build the FAE for your board:

cd rustlets/rustlet_template

# Pico 1:
RUSTLET_TARGET=thumbv6m-none-eabi cargo build-fae

# Pico 2: use this command instead:
# RUSTLET_TARGET=thumbv8m.main-none-eabihf cargo build-fae

cd ../..

Deploy the package, select its instance, then send instruction 04:

target/debug/apdu_tool --progress gp deploy \
  A0000047504F5321 \
  rustlets/rustlet_template/build/rustlet_template.fae \
  A0000047504F5322 --security-domain A0000047504F5301

target/debug/apdu_tool select A0000047504F5322
target/debug/apdu_tool raw 00:04:00:00:00:02

The final command must return CA FE and status 90 00. Close the local client session when finished:

target/debug/apdu_tool close

This removes session.json; it does not uninstall the Rustlet from the Pico.

A development configuration.The devkit uses a permissive root and no Secure Channel. Anyone with access to the APDU link may request deployment. It is for prototyping, not production security policy.
