Prototype your first Rustlet.

For Rust developers who want to try a small isolated application on a Secure Element research platform.

First outcome

A running devkit image, one loaded Rustlet and a successful APDU exchange.

Before you begin

Choose the shortest path.

The shortest repeatable loop starts with Pico 1 under the project’s QEMU fork. The board catalogue also includes other QEMU and hardware targets; follow each target’s documented runner and prerequisites.

Prerequisites

  • The Rust nightly selected by the repository, Cargo and ARM GNU tools.
  • QEMU build dependencies for the Pico 1 software path.
  • For hardware: a Pico, a CMSIS-DAP-compatible SWD probe, OpenOCD with RP2040 support and a 115200-baud UART bridge.

Build

Create the devkit image.

  1. Clone the pinned beta.Check out the release tag and its two recorded submodules.
  2. Install the documented tools.Follow the versioned setup guide for host and target prerequisites.
  3. Build the permissive manifest.Use the devkit composition for your chosen target; the Pico 1 example is shown below.
git clone --recurse-submodules --branch v0.9.0-beta.2 \
  https://github.com/oxide-se/oxide-se.git
cd oxide-se
cargo run build --config configs/config_devkit.toml raspi-pico1

The expected artifact is target/kernel/firmware/kernel.elf.

Build stops at an ELF.It does not flash a board or start QEMU. Choose one of the startup paths in the getting-started guide next.

Run

Boot, load, exchange.

  1. Start the target.Use the pinned fork for Pico 1 QEMU, or the documented QEMU/OpenOCD runner for another supported target.
  2. Connect the APDU tool.QEMU exposes a serial socket. Hardware uses the UART bridge; provide --serial when more than one port is present.
  3. Load a first Rustlet.Follow the dynamic-loading walkthrough, then select the application and exchange its first APDU.

For the documented Pico 1 QEMU path, build the host tool before boot and keep the socket path consistent:

cargo build -p apdu_tool
tooling/qemu-rp2040-pico/build/qemu-system-arm \
  -machine raspi-pico -display none -monitor none \
  -chardev socket,id=serial0,path=/tmp/oxide-se-pico1.sock,server=on,wait=on \
  -serial chardev:serial0 \
  -semihosting-config enable=on,target=native \
  -kernel target/kernel/firmware/kernel.elf

In a second terminal, receive the one-time boot ATR, build the checked tutorial Rustlet for Pico 1, then deploy and select it:

target/debug/apdu_tool -v \
  --serial /tmp/oxide-se-pico1.sock \
  --atr-timeout infinite atr

cd rustlets/tests
RUSTLET_TARGET=thumbv6m-none-eabi cargo run build-fae getting_started_test
cd ../..

target/debug/apdu_tool --progress gp deploy \
  A0000047504F5320 \
  rustlets/tests/getting_started_test/build/rustlet_getting_started_test.fae \
  A0000047504F5320
target/debug/apdu_tool select A0000047504F5320
target/debug/apdu_tool raw 00:04:00:00:00:03

The final command should return 10 11 12 and status 90 00. The ATR command creates session.json; run the remaining commands from the same directory and do not read the ATR again during that boot.

A development configuration.The devkit uses a permissive root and no Secure Channel. Anyone with access to the APDU link may request deployment. It is for prototyping, not production security policy.

Authoring

Create your own Rustlet.

Copy the standalone template beside rustlet_runtime, rename the package in its Cargo.toml, and implement the APDU handler in src/main.rs. For the Pico 1 devkit above, keep the ARMv6-M target:

cp -R rustlets/rustlet_template rustlets/my_first_rustlet
cd rustlets/my_first_rustlet
RUSTLET_TARGET=thumbv6m-none-eabi cargo build-fae
cd ../..

Deploy the resulting rustlets/my_first_rustlet/build/my_first_rustlet.fae with an unused test AID, then select that same instance AID. Changing a Rustlet does not require rebuilding or reflashing the running devkit.

Open the Rustlet API reference →

The versioned Rustdoc documents Rustlet, declare_rustlet!, typed APDU processing, persistence and kernel-backed cryptographic services. Keep it open while implementing src/main.rs.

Two documented routes.The development-kit walkthrough uses dynamic loading on Pico 1. The separate Rustlets getting-started exercise demonstrates template authoring through a predeployed mps2-an385 image and therefore uses thumbv7m-none-eabi. Do not mix its target triple or transport with the Pico 1 commands above.
