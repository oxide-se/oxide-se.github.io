01 / Devkit

Prototype your first Rustlet.

For Rust developers who want to try a small isolated application on a Secure Element research platform.

First outcome

A running devkit image, one loaded Rustlet and a successful APDU exchange.

Before you begin

Choose the shortest path.

The shortest repeatable loop starts with Pico 1 under the project’s QEMU fork. The board catalogue also includes other QEMU and hardware targets; follow each target’s documented runner and prerequisites.

Prerequisites

  • The Rust nightly selected by the repository, Cargo and ARM GNU tools.
  • QEMU build dependencies for the Pico 1 software path.
  • For hardware: a Pico, a CMSIS-DAP-compatible SWD probe, OpenOCD with RP2040 support and a 115200-baud UART bridge.

Build

Create the devkit image.

  1. Clone the pinned beta.Check out the release tag and its two recorded submodules.
  2. Install the documented tools.Follow the versioned setup guide for host and target prerequisites.
  3. Build the permissive manifest.Use the devkit composition for your chosen target; the Pico 1 example is shown below.
git clone --recurse-submodules --branch v0.9.0-beta.1 \
  https://github.com/oxide-se/oxide-se.git
cd oxide-se
cargo run build --config configs/config_devkit.toml raspi-pico1

The expected artifact is target/kernel/firmware/kernel.elf.

Build stops at an ELF.It does not flash a board or start QEMU. Choose one of the startup paths in the getting-started guide next.

Run

Boot, load, exchange.

  1. Start the target.Use the pinned fork for Pico 1 QEMU, or the documented QEMU/OpenOCD runner for another supported target.
  2. Connect the APDU tool.QEMU exposes a serial socket. Hardware uses the UART bridge; provide --serial when more than one port is present.
  3. Load a first Rustlet.Follow the dynamic-loading walkthrough, then select the application and exchange its first APDU.
A development configuration.The devkit uses a permissive root and no Secure Channel. Anyone with access to the APDU link may request deployment. It is for prototyping, not production security policy.
