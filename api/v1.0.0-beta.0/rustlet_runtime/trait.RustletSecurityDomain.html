Expand description

Management and secure-channel interface implemented by Security Domain Rustlets.

A Security Domain Rustlet remains a normal selectable Rustlet through Rustlet::process_apdu, but it also exposes management and secure-channel hooks that the kernel can call through the dedicated Security Domain proxy. Administrative privilege is not privileged CPU execution. The kernel keeps ownership, hierarchy and non-escalation checks; returning Ok here cannot grant authority beyond those checks. Authorization hooks do not themselves commit registry mutations.

Request slices and output buffers are loans for this invocation only. Do not retain them in instance state. Output hooks write into out and return the initialized prefix length, at most out.len(); on error, output must not be published. In-place unwrap/wrap is an ABI optimization handled by the proxy, not permission to construct overlapping mutable Rust references.

Defaults deny unimplemented protocol operations with 6D00, advertise no protocol, and report no open channel. Management defaults require a selectable lifecycle and the relevant privilege and otherwise return 6985. get_data supplies discovery/lifecycle objects and reports missing or unsupported tags. Override protocol hooks and capability queries together.

With declare_security_domain!, the persistent wrapper owns administrative state. Its active secure-channel state can remain resident between calls; exclude session secrets from serde and erase them in reset_secure_channel. SCP03 key loading is available only during kernel-initiated SDDISPATCH.

§API map

  • Management policy: Self::install_for_load, Self::install_for_install, Self::delete_aid, Self::put_key, Self::store_data, Self::set_status and Self::get_data.
  • Establishment: Self::handle_delegated_secure_channel_command, Self::initialize_update, Self::external_authenticate and the scp11_* hooks below. Advertise only implemented protocol capabilities.
  • Secure messaging: Self::unwrap_command, Self::wrap_response, Self::current_security_level and Self::reset_secure_channel.
  • Kernel key service: crate::RuntimeSyscall::SecurityDomainLoadScp03Key, crate::Scp03LoadKeyParams and crate::syscall::runtime::crypto::load_scp03_key::trigger. This service is denied during ordinary process_apdu and installation, even for an SD.
  • Shared cryptography: crate::CryptoProvider, crate::Cipher, crate::Mac and crate::KeyAgreement.

§Current rollback limitation

A normally rejected management operation restores its staged registry changes, but does not yet restore the persistent fields of the resident SD object. A later call can serialize those abandoned changes again. Do not assume an error return restores self. Session serialization and separate persistent/session restoration are not implemented yet.
